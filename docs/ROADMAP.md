## 2026-11-23 已上线

Assistant `2b15e6e` 和 Web `8dc0967` 已在正式 Docker 环境运行。正式库已备份并应用 `0031_intake_replies` 和 `0032_intake_capture`。发布前通过真实 Nexus 和 `opencode/glm-5.3-flash` 在隔离数据中验收，发布后核对了服务健康、后台心跳和账号保留情况。[部署与验收记录](部署记录.md#2026-11-23-对话续接与随手记发布)

| 能力 | 发布范围 |
| --- | --- |
| 连续对话 | 近期历史与实际业务回执帮助定位已有日程和待办。模型按原编号先读现行记录，再执行业务修改。 |
| 追问续接 | 刷新后可以直接回答待回复追问。独立新话题单独处理，过期追问仍可从历史手动续接。 |
| 随手记 | 提交后由后台处理。需要确认的安排出现在「今天」，用户选择新时段后重新检查冲突。 |
| 进度与恢复 | 「问助手」显示执行阶段，刷新后恢复同一任务及最终卡片。首轮提供查询和创建日程的参数定义。 |

## 待交付

- **阶段一串联验收**。验证从随手输入会议文字、采用相关记忆，到「今天」推荐下一步并完成或调整的完整路径。
- **阶段二持续关注、自动重排与简报**。继续补齐外部来源授权、变化判断和安静汇报规则，再验证结合日程、待办、作息与逐段交通的全天重排。自动通勤按既有正式配置开启。
- **阶段三场景能力包与 iOS 入口**。按产品规划推进工作接续、看病办事和短途出行模板，以及 iOS 分享、快捷输入和小组件。

## 历史决策

早期产品是看板与聊天，保留了 Electron IPC、Prisma/SQLite 和 Web 看板实现。Phase 1 的历史实现见[变更记录](../CR-2026-06-16.md)。后续看板 Phase 2–5 已被当前产品规划替代。

项目复用 Nexus 的模型调用、Agent 和运行记录。Assistant 处理业务与界面。单 Agent 正文处理的实现及历史验证范围见[接口复核与 AI 业务调用说明](backend-integration/27-接口复核与AI业务调用说明.md)。

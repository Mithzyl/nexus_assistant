# 02 架构与调用链

> 更新：2026-11-05。当前工作区实现；部署及完整验收状态见[27](27-接口复核与AI业务调用说明.md)。已删除旧主体解析假设及单步重建 Agent 的执行建议。

## 职责

| 组件 | 负责 |
| --- | --- |
| Web / iOS | 用户输入、身份会话、最终回答和卡片；不持有 Nexus 服务端凭据 |
| Assistant API | 账号、事项/日程/待办、业务 OpenAPI、权限、版本与事务；用户原文及 AI/后端来源保存 |
| Nexus API / Agent 执行进程 | 模型与提供商、Agent 消息、正文处理 HTTP 等待、执行记录、继续及终答 |
| Assistant scheduler / worker | 已保存的补充分析、跟进及通勤任务；不是另一套模型规划循环 |

## 当前路径

1. 客户端通过 Assistant 会话提交用户输入。Assistant 保存当前用户、事项关联、时间、来源明确的历史和请求标识。
2. Assistant 创建并保存一个 Nexus Run/Workflow，提供本次业务说明及 caller_processed 配置。服务端通过应用凭据和 X-External-User-Id 绑定身份。
3. Nexus 将完整模型正文交给已批准的 Assistant `/internal/nexus/agent-responses`，不解析具体 operation_id。
4. Assistant 解析 decision，校验业务并经过原路由执行，返回关联 execution_id 的实际状态和结果。此回调不进入问助手入口，不发起另一轮 Agent。
5. Nexus 追加原始 assistant 正文及标记来源的 backend_execution_result，沿用原 Agent 再调用模型；没有结果未知的写入重发。
6. 模型自行终答或追问。平台确认候选结果、Nexus 完成最终检查后，Assistant 转换为现有页面协议并保留历史读取。

## 保存与通信

`nexus_runs` 保存运行映射、输入、业务关联与最终结果；新增 `agent_response_receipts` 保存原正文、实际执行参数和回执。现有 `tool_call_receipts` 服务旧 `/internal/nexus/tools` 只读工具，不用于替代正文回调。

回调地址、服务端凭据和可信用户来自批准的应用连接及运行记录；模型只提供业务参数。接口通信、未知结果和重复执行的完整规则统一在[27](27-接口复核与AI业务调用说明.md)，不在此重复维护协议字段。

当前实现需要 Assistant 0026 和 Nexus 0051/0052 对应结构。库迁移、服务加载和真实 Worker/存储验收未因文档或临时 SQLite 建表而完成。

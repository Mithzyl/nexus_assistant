# 02 架构与调用链

## 1. 系统架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Personal Assistant Frontend (Next.js / React)                │
└───────────────────────────┬──────────────────────────────────┘
                            │ Bearer <PA session token>
┌───────────────────────────▼──────────────────────────────────┐
│ Personal Assistant API (FastAPI, 独立进程 / 独立数据库)        │
│                                                              │
│  auth         本地账号、会话（只存 token 摘要）                │
│  assistant    交入、状态、SSE 代理、取消、记忆召回             │
│  internal_*   业务工具回调（供 NexusPilot 调用）               │
│                                                              │
│  users / user_profiles / user_sessions                       │
│  tasks / schedules / notes / business_records                │
│  nexus_identity_links   ← 旧投影，当前运行路径不再使用          │
│  nexus_runs             ← 运行引用、工作流 id、最终回答、游标    │
│  tool_call_receipts     ← 工具调用幂等回执                    │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS + SSE
                            │ Authorization: Bearer <应用令牌>
                            │ X-Application-Id
                            │ X-External-User-Id（服务端设置）
┌───────────────────────────▼──────────────────────────────────┐
│ NexusPilot API (FastAPI, 既有进程)                            │
│                                                              │
│  features/applications  ← 新增：应用、主体、映射              │
│  features/identity      ← 既有：资源归属（复用）              │
│  features/agent_runtime ← 既有：工作流、工具循环、SSE         │
│  services/              ← 既有：Run/Task/Attempt、工具目录     │
│                                                              │
│  llm_runs / llm_tasks / llm_attempts                         │
│  llm_agent_workflow_executions / _node_executions / _events  │
│  llm_tool_calls / llm_memories / user_files                  │
└───────────────────────────┬──────────────────────────────────┘
                            │
          ┌─────────────────┴─────────────────┐
          ▼                                   ▼
      MySQL 8.4                            MinIO
   数据库 nexuspilot（不新增库）          对象存储
```

Personal Assistant 另有自己的 database（逻辑隔离，可与 NexusPilot 同实例），两者之间**没有任何跨库查询**。

## 2. 数据所有权

| 数据 | 所有者 | 对方如何获得 |
|---|---|---|
| 用户账号、密码、会话 | Personal Assistant | NexusPilot 永不读取 |
| 任务、日程、笔记、账目 | Personal Assistant | 只能通过业务工具回调 |
| 应用注册与凭据 | NexusPilot | PA 持有明文令牌，NexusPilot 只存摘要 |
| 主体与映射 | NexusPilot | PA 缓存投影，冲突时以 NexusPilot 为准 |
| Run / Task / Attempt | NexusPilot | PA 只存 `run_id` 引用 |
| Agent 事件 | NexusPilot | PA 转发，不落全量副本 |
| 记忆 | NexusPilot | PA 通过 API 召回，不存本地副本 |
| AI 文件与产物 | NexusPilot | PA 只存 file/artifact id |

判断规则：**任何一方需要对方数据时，走 API；任何"顺手 join 一下"的想法都视为越界。**

## 3. 链路 A：提交与启动工作流

```text
PA 前端          PA API                 NexusPilot
   │  POST /asks   │                        │
   │──────────────>│                        │
   │               │ 1 验证 PA 会话          │
   │               │ 2 本地 (user,key) 去重  │
   │               │ 3 POST /app/runs        │
   │               │   X-Application-Id      │
   │               │   X-External-User-Id    │
   │               │   {"user_request": ...} │
   │               │───────────────────────>│
   │               │                        │ 4 校验应用 + 解析/创建 mapping
   │               │<───────────────────────│ run_id (201)
   │               │ 5 POST /app/runs/{id}/agent-workflows
   │               │   stream=true, general_agent
   │               │   role_bindings 来自服务端配置
   │               │───────────────────────>│
   │               │<───────────────────────│ SSE: 首帧含 workflow_id
   │<──────────────│ 202 {local, run, workflow, status=running}
   │               │ 6 后台继续消费到终态
   │               │ 7 GET /result → 只持久化 final_output.final_text
```

关键点：

- 当前 NexusPilot 在认证应用时解析应用用户；**没有** `/principals/resolve`，也没有
  `pilot_principals` 前置步骤。PA 不再等待身份映射。
- `role_bindings` 是当前 `AgentWorkflowCreate` 的必填字段，由 assistant-api 的
  `ASSISTANT_NEXUS_ROLE_BINDINGS_JSON` 提供；不是客户端输入，也不进入响应。
- 工作流必须使用 `general_agent` / `1.0.0` / `general_tools_v1`；应用路由会额外校验。
- 创建 Run 没有上游 idempotency_key；PA 自己 `(user_id, idempotency_key)` 唯一约束是防重层。
- 创建 Run 超时：本地 `unknown`，不自动重试。工作流首帧超时：`unknown`，不假装已启动。
- 任意一步失败，PA 落明确 `failed` / `unknown`，不返回“已受理”。

## 4. 链路 B：订阅与恢复

```text
PA 前端                 PA API                    NexusPilot
   │ GET /asks/{id}/events  │                          │
   │ Last-Event-ID: 42      │                          │
   │───────────────────────>│ 查本地 run（归属校验）    │
   │                        │ GET /app/agent-workflows/{wf}/events
   │                        │ Last-Event-ID: 42
   │                        │─────────────────────────>│
   │                        │<─────────────────────────│ 43,44,45...
   │<───────────────────────│ 逐帧转发 + 记录最大序号    │
   │                        │                          │
   │   （连接中断）           │                          │
   │ GET /asks/{id}/events  │                          │
   │ Last-Event-ID: 45      │                          │
   │───────────────────────>│ 从 45 之后继续            │
```

- 事件 id 直接使用 `event_sequence`，与 NexusPilot 的 `Last-Event-ID` 解析一致
  （`routers/agent_workflows.py` 中只接受非负整数）。
- 当前上游 `/events` 是**已持久化事件的有限回放**，不是无限实时订阅；PA 不伪造实时进度。
- 终态后 PA 调 `/result` 取 `final_output.final_text` 并写入本地 `nexus_runs.result_json`；
  刷新 `GET /asks/{id}` 会重新对账，而不依赖原 SSE 连接。
- 上游断开时返回一帧 `assistant.error`，而不是静默结束。客户端因此不会把"连接断了"当成"做完了"。

## 5. 链路 C：工具回调

```text
NexusPilot Agent Runtime        PA API
   │ 模型产出 ToolCall            │
   │ 参数校验通过                 │
   │ 生成 tool_call_id            │
   │ POST /internal/nexus/tools
   │ Authorization: Bearer <service_token>
   │ {"tool_execution_id","application_id","external_user_id",
   │  "tool_name","tool_version","arguments"}
   │─────────────────────────────>│
   │                              │ 1 校验服务令牌
   │                              │ 2 校验 application/版本/工具名
   │                              │ 3 查回执（命中即原样返回）
   │                              │ 4 external_user → 本地用户
   │                              │ 5 校验参数 schema（extra=forbid）
   │                              │ 6 按 user_id 过滤查询
   │<─────────────────────────────│ {"items":[...],"next_cursor":null}
```

模型看到的工具 schema 里没有 `user_id`、`principal_id`、`app_id` 任何字段。即使模型执意构造，第 5 步会以 `invalid_tool_arguments` 拒绝。

## 6. 失败语义

| 情况 | PA 对前端 | PA 本地状态 | 是否自动重试 |
|---|---|---|---|
| 应用令牌无效 | 502 `nexus_application_unauthenticated` | failed | 否，需运维修配置 |
| 无权使用该模型/工具 | 502 `nexus_permission_denied` | failed | 否 |
| 创建 Run 超时 | 504 `nexus_timeout` | **unknown** | 否，未知结果不重放 |
| NexusPilot 5xx | 503 `nexus_unavailable` | failed | 可重试（同一幂等键） |
| 工作流启动失败 | 502/503 | failed，保留 `nexus_run_id` | 否，先对账 |
| SSE 中断 | 已发事件 + `assistant.error` | 保持 running，记 `error_code` | 客户端带 `Last-Event-ID` 重连 |
| 用户主动取消 | 200 `cancelled` | cancelled | — |

`unknown` 是刻意保留的状态：它表示"远端可能已经创建了 Run，但我们没拿到回执"。把它当失败处理会导致重复计费与重复执行。

## 7. 为什么不在 PA 里再写一套 Agent

现有 `general_agent_orchestrator` 已经包含规划、工作节点、交接、Reviewer、确定性验证与终止条件。再写一套会产生三份不一致的实现：工具权限、超时、Token 计费、事件序号。PA 侧只保留"调用 + 转发 + 业务工具"，是唯一能保证两边语义一致的切法。

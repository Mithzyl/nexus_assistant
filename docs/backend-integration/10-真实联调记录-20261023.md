## 2. 两条真实 App 请求

两条请求都成功经过 PA 登录、Run 创建、工作流启动、SSE 消费和本地持久化；在调用
DeepSeek 时，上游返回 **HTTP 402 Insufficient Balance**，因此没有生成最终回答。

| 场景 | 请求 | 结果 | 耗时 | 运行状态 | token 用量 | 失败原因 |
|---|---|---|---|---|---|---|
| A 普通问题 | “用一句话解释任务清单，不调用工具” | HTTP 202，工作流已创建 | 2.399 s | `failed` | 0 / 0 / 0 | `provider_error / invalid_request`：`Model provider returned HTTP 402.` |
| B 工具问题 | “调用 personal_assistant_list_tasks 读取我的任务并列出” | HTTP 202，工作流已创建 | 2.320 s | `failed` | 0 / 0 / 0 | 同上；`tool_call_count=0`，未到工具调用阶段 |

PA 本地记录分别是 `failed`，没有伪造 `succeeded` 或 `answer`；刷新读取仍为 `failed`。
失败是**确定性且可区分**的，没有自动重试创建付费运行。

> 结论：真实 DeepSeek 回答被计费状态阻塞，不是 PA/NexusPilot 协议错误。需要给
> NexusPilot 配置的 DeepSeek 账号充值或换用可用 key，才能完成 A/B 的最终回答与
> token 用量记录。

## 3. 真实工具 HTTP 格式验证

在不触发模型的情况下，直接用 NexusPilot 的 `RemoteToolAdapter` 调用 PA 真实工具端点：

- 请求：扁平 envelope + `Authorization: Bearer <service_token>`，无旧 `X-NexusPilot-*` 头。
- 工具：`personal_assistant.list_tasks`，版本 `1.0.0`。
- 输出经 NexusPilot `BusinessReadResult` 校验通过，只含 `items` / `next_cursor`。
- 用户 A 返回 1 条自己的 synthetic task；用户 B 返回 1 条自己的 synthetic task，标题不同。
- 同一 `tool_execution_id` 重放返回同一结果，PA 不重复执行。
- 直接工具回调使用错误用户/工具或未登记工具时拒绝；详见第 3 节。

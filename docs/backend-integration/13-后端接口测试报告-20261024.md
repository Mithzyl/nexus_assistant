## 5. 发现、修复与未修复项

### 5.1 已修复：SSE 重放改写 `completed_at`

- 条件：对已完成 run 再次 `GET /api/v1/asks/{id}/events`。
- 修复前：`completed_at` 从 `2026-10-24T01:02:43.431643Z` 变为 `2026-10-24T01:04:35.624901Z`；即有限回放把完成时间刷新成“现在”。
- 原因：`record_progress()` 只要收到终态事件就无条件写 `completed_at`。
- 修复：仅在首次进入终态或从 `unknown` 恢复时写；重放保持原值。
- 回归：`tests/test_sse_resume.py::test_replaying_completed_events_preserves_completed_at`。
- 真实 HTTP 验证：同一已完成 run 重放 SSE 后 `completed_at` 不变。
- 文件：`services/assistant-api/src/assistant_api/services/run_service.py`。

### 5.2 已修复：取消已完成 run 返回 502 / 改成 cancelled

- 条件：`POST /api/v1/asks/{id}/cancel`，该 run 已 `succeeded`。
- 修复前：真实服务返回 **502**；单元 fake 下状态从 `succeeded` 被改成 `cancelled`。
- 原因：`cancel_run()` 不判断本地终态，继续转发上游取消；上游拒绝后映射成 502；fake 返回 cancelled 时又覆盖本地状态。
- 修复：本地 `succeeded/failed/cancelled` 直接返回原行，不调用上游；重复取消幂等。
- 回归：`tests/test_run_flow.py::test_cancel_after_completion_is_truthful_and_local`。
- 真实 HTTP 验证：完成后的取消返回 200 `status=succeeded` 且 answer 保留；重复取消相同。
- 文件：`services/assistant-api/src/assistant_api/services/run_service.py`。

### 5.3 已修复：同一 `tool_execution_id` 携带不同参数返回旧数据

- 条件：同一 execution id、同一用户、同一工具，先 `{"limit":10}`，再 `{"limit":1}`。
- 修复前：200 + `X-Idempotent-Replay: true`，返回第一次的 3 条任务；不同参数被静默忽略。
- 修复：新增 `arguments_sha256`（nullable），新回执写入规范化参数摘要；重复 ID 参数不同返回 **409 `tool_call_arguments_mismatch`**；参数相同仍复用原回执；旧回执首次重放时回填摘要。
- 回归：`tests/test_tool_callback.py::test_same_execution_id_with_different_arguments_is_refused`。
- 真实 HTTP 验证：同 ID 改 `limit` 返回 409；原参数重放 200。
- 文件：
  - `services/assistant-api/src/assistant_api/models/bridge.py`
  - `services/assistant-api/src/assistant_api/routers/internal_tools.py`
  - `services/assistant-api/migrations/20261024_tool_receipt_arguments.sql`（新增）
- 部署注意：现有数据库需执行该迁移；测试库已手工 `ALTER TABLE`，正常库未动。

### 5.4 未修复：同一数据来源 `batch_id` 携带不同内容静默返回旧结果

- 条件：同一 `source_id`、同一 `batch_id`，第二次提交不同 `external_id/title`。
- 实际：200，返回第一次的 `created=1` 计数与旧 `last_sync_at`；第二次内容未写入。
- 影响：客户端若误复用 batch_id，不会收到冲突，可能以为新内容已上传。
- 状态：**未修复**。修复需要为 `content_sync_batches` 增加请求摘要并返回 409，属于新的 schema/协议决策；本轮只报告，未扩大范围。
- 建议：增加 `request_sha256`（nullable）迁移；同 ID 不同摘要返回 409；旧批次回填策略单独评审。

### 5.5 环境问题：配置端口与实际 Nexus 不一致

- 私有 env：`ASSISTANT_NEXUS_BASE_URL=http://127.0.0.1:8001`。
- 实际：8001 无监听；8000 是运行中的 NexusPilot 0.8.0，现有 app 凭据有效。
- 处理：仅在隔离测试启动命令中覆盖为 8000；未改配置文件、未改供应商、未改模型。
- 风险：按现有 env 直接启动 PA 会无法访问 Nexus；部署前必须对齐端口或恢复 8001。
- 另：仓库内没有 `.env`；真实配置在私有临时 env 中，未入库。仓库 `.venv` 指向不存在的 Python 3.13，本轮使用 `/tmp/pa-venv311`（Python 3.11.9）。

### 5.6 测试设施修正：`lost create response` 原来只丢弃 JSON

- 原 e2e 的 `lost_create_response` 只是客户端不解析第一次响应，不是“服务端已受理、响应未送达”。
- 本轮新增 TCP 代理：转发请求到 PA，读到 202 后关闭客户端连接，不发送响应；随后用原 text + 原 key 重放。
- 结果：19/19 中包含 `lost 202 at transport`，同一 local run、上游只创建一次。
- 文件：`services/assistant-api/scripts/e2e_check.py`。

# 智能通勤分析契约

更新：2026-10-24。接口仍为：

```text
POST /api/v1/commute-plans/{plan_id}/checks
GET  /api/v1/checks/{check_id}
GET  /api/v1/commute-plans/{plan_id}/advisories/latest
```

`POST` 返回 202 只表示**已受理**，不代表模型分析完成。客户端必须继续查询 check 状态和建议。

## 路线来源

| 请求 | 路线来源 | `ai_analysis.route_source` |
|---|---|---|
| 带 `route_snapshot` | 客户端 MapKit 快照 | `client_snapshot` |
| 不带 body，服务端路线 Provider 可用 | 服务端查询 | `server_provider` |
| 不带 body，服务端 Provider 未配置 | 无 | `none` |

- 旧客户端无 body 请求仍兼容，自动走服务端路线 Provider。
- 服务端 Provider 未配置时返回 `route_provider_unconfigured`，不编造距离/ETA，不调用模型。
- 客户端只能提交 `route_snapshot`；不能指定供应商 URL、服务器凭据或模型名。
- 自动检查继续入队以刷新 Open-Meteo 天气；服务端路线 Provider 不可用时只跳过路线查询和模型分析，不跳过天气任务。App 手动检查和客户端快照不受影响。

## advisory.ai_analysis

```json
{
  "status": "available",
  "analysis_version": 2,
  "route_source": "client_snapshot",
  "used_duration_seconds": 1559,
  "duration_source": "duration_in_traffic_seconds",
  "map_duration_seconds": 1559,
  "base_buffer_seconds": 600,
  "additional_buffer_seconds": 0,
  "extra_buffer_seconds": 600,
  "recommended_departure_at": "2026-10-24T13:54:01Z",
  "basis": ["采用含交通 ETA 1559 秒", "固定缓冲 600 秒", "降水风险未触发额外缓冲"],
  "missing_information": ["无实时拥堵事件"],
  "reason": null
}
```

字段：

- `analysis_version`：新逻辑为 `2`；缺失表示旧版本结果，不代表新字段为 0；
- `status`：`available | unavailable | rejected`；
- `route_source`：`client_snapshot | server_provider | none`；
- `used_duration_seconds`：最终采用的耗时；
- `duration_source`：`duration_in_traffic_seconds | duration_seconds | none`；
- 快照同时存在 `duration_in_traffic_seconds` 时，后者优先；即使数值与基础耗时相同，也不会把来源标成基础耗时；
- `map_duration_seconds`：本次采用的地图耗时；
- `base_buffer_seconds`：计划固定缓冲，是用户约束；
- `additional_buffer_seconds`：模型在固定缓冲外建议的额外预留；
- `extra_buffer_seconds`：两者之和；
- `recommended_departure_at`：必须满足 `target_arrival - used_duration - extra_buffer`；
- `basis` / `missing_information`：模型依据与缺失项；
- `reason`：不可用或拒绝原因。

只有真实 Nexus 结果通过校验才出现 `status=available`，同时：

```json
"explanation_source": "model"
```

`title`、`summary`、`ai_analysis.recommended_departure_at` 来自同一份校验结果。模型原始
`final_text` 保留在对应用户的 `nexus_runs.result_json`，`ai_run_id` 指向该运行。

## 新旧结果区分

- `analysis_version=2` 且带有 `route_source`、`base_buffer_seconds`、
  `additional_buffer_seconds`：新逻辑实际保存到 `ai_analysis_json` 的值；
- 缺少这些字段：旧版本 advisory。读取端必须显示“旧版本/字段未知”，不能把缺失的
  `additional_buffer_seconds` 当成 0，也不能把旧 `quality` 当成新逻辑验收证据；
- 旧 advisory 不重写；原始模型文本仍在 `nexus_runs.result_json`，历史校验结果仍保存在
  原 advisory 中；
- 新代码的推导值不会自动回填到旧行；需要新分析才能得到 v2 结果。

## latest 规则

`GET /commute-plans/{plan_id}/advisories/latest` 的定义是：

> 该计划按 `generated_at` 最新的一条已保存 advisory，包含 `available`、`degraded` 和
> `unavailable`；它**不是**“最新有效/可用建议”。

因此客户端应优先：

1. 用 `GET /checks/{check_id}` 取得该次检查的 `advisory_id`；
2. 用 `GET /advisories/{advisory_id}` 读取对应结果。

不要用 latest 代替指定 check 的结果，也不要用测试计划污染 App 计划的 latest。

## quality

`quality` 只按本次实际采用的数据判断：

- 采用客户端快照或服务端路线，且天气新鲜 → 不因未参与的其他供应商缺失而降级；
- 天气过期、缺少覆盖范围或路线不可用 → 对应降级/不可用；
- 客户端快照不是 Apple 签名数据，`source_note` 保留该事实。

`weather_extra_buffer_seconds` 只表示天气相关额外缓冲；固定缓冲仍在 `buffer_seconds`。

## 不可用原因

| reason | 含义 |
|---|---|
| `route_provider_unconfigured` | 无客户端快照且服务端路线 Provider 未配置 |
| `route_provider_unavailable` | 服务端路线 Provider 已配置但本次查询失败/超时 |
| `route_snapshot_stale` | 已保存快照超出新鲜窗口，需要刷新 |
| `ai_nexus_not_configured` | 后端未配置 Nexus 客户端 |
| `ai_timeout` | 上游分析超时，结果未确认 |
| `ai_workflow_failed` | 工作流失败 |
| `ai_upstream_error` | Nexus 调用异常 |
| `ai_output_invalid_json` | 模型输出不是严格 JSON |
| `ai_duration_not_from_snapshot` | 采用耗时不在快照中 |
| `ai_departure_arithmetic_invalid` | 出发时间算术不一致 |
| `ai_duration_source_invalid` | 来源与耗时字段不一致 |
| `ai_extra_buffer_invalid` | 固定/额外缓冲不一致 |
| `ai_route_reference_invalid` | 引用了不存在的路线 |

`unavailable`/`rejected` 不等于“没有检查”；失败原因保留，不使用固定模板冒充 AI 成功。

## 幂等与恢复

- 同一 `Idempotency-Key` + 同内容复用同一 check；
- 同内容重复查询返回同一 check；
- 不同内容返回 `409 idempotency_key_reused`；
- 旧 `plan_revision` 返回 `409 plan_revision_conflict`；
- AI Nexus 运行使用 `commute-ai:{check_id}:{snapshot_hash}` 幂等键，重复执行不创建第二次工作流；
- 查询 check/advisory、页面刷新和服务重启不会新建 AI run；
- 恢复先按保存的 `nexus_run_id` 对账；只有幂等键、没有 run id 的崩溃窗口返回
  `ai_run_mapping_unknown` / `unknown`，不盲目新建 run（幂等键不是所有崩溃点的安全证明）；
- 旧计划 revision 的迟到结果被丢弃，不覆盖新建议；
- check 的 `status` 与 `phase` 分离；`phase_updated_at` 是任务进度，进程心跳另见
  `/api/v1/commute/runtime`。`weather_only` 只刷新天气，不新建 advisory、不改 latest。
  完整字段见 [../commute/runtime-contract.md](../commute/runtime-contract.md)。

## 当前限制

- 客户端快照不是 Apple 服务端签名验证；
- 服务端路线 Provider 尚未配置时只能返回明确的未配置状态；
- 总体 ETA 不得冒充候选路线 ETA；
- 天气只覆盖起点/终点时，不宣称覆盖整条道路。

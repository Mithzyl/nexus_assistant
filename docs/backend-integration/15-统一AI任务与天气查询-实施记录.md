未重写后台调度；未新增真实模型调用；未发送通知；未提交、推送或部署。

## 1. 结论

- 用户提问与内部人工智能运行已分开：`user_asks` 只表示“用户在聊天里提出过这个问题”，
  执行状态与最终答案仍然只在 `nexus_runs`，没有第二份状态。
- `nexus_runs` 成为共用的人工智能任务记录：`purpose`、`business_ref`、`input_version`、
  `trigger` 全部由服务器根据已校验的业务记录写入，公开请求不能指定。
- 通勤在**创建本地运行的同一次提交**里写入 `commute_checks.ai_run_id`，不再依赖后续
  阶段更新；失败、超时、结果未知同样保留关联。
- 聊天列表、详情、事件、取消都从 `user_asks` 出发，内部运行不再出现在聊天历史里，
  也不会被聊天接口读上游或取消。
- 新增天气查询、建议适用性标注、旧缓存核对接口；后台调度与 Nexus 客户端未改。

## 3. 新增字段、关联表与接口

**`nexus_runs` 新增列（可空，供迁移分类）**
`purpose`（`chat` / `commute_internal` / `legacy_unknown`）、`business_ref`、
`input_version`、`trigger`（`chat` / `manual` / `schedule`）。
新增索引 `(purpose, business_ref)`、`(user_id, purpose, created_at)`。
既有唯一键 `(user_id, idempotency_key)` 保留，是新旧客户端重放的基准。

**`user_asks`（新表）**：`ask_id`、`user_id`、`local_run_id`（唯一，外键到运行）、
`request_text`、`created_at`、`updated_at`。不含状态、答案、模型输出。

**迁移**：`migrations/20261025_ai_task_purpose.sql`，并在 `scripts/migrate_sqlite.py`
登记 `0006_ai_task_purpose`（列 + 索引，重复执行记录 `already_present`）。

**接口**
| 方法 | 路径 | 变化 |
|---|---|---|
| POST | `/api/v1/asks` | 同时创建提问关联；路径、`local_run_id`、返回字段不变 |
| GET | `/api/v1/asks` | 从提问关联查询，按提问时间倒序 |
| GET/POST | `/api/v1/asks/{id}`、`/events`、`/cancel` | 先确认当前用户的提问关联，否则 404，且不触达上游 |

## 4. 三类调用如何使用统一服务

**聊天**（`routers/assistant.py` → `run_service.start_chat_ask`）
1. 会话解析出用户；`idempotency_key` 在请求体。
2. `create_ai_task(purpose=chat, trigger=chat)` 在一个事务里写入 `nexus_runs` 与
   `user_asks`；同键同文返回原记录，同键异文 409。
3. 提交完成后才调用 Nexus；随后由后台观察者把状态与 `final_text` 写回运行记录。
4. 用户正常输入 JSON、坐标或“怎样写通勤分析提示词”都不会被文字过滤。

**通勤**（`commute/services/ai.analyze`）
1. 先按 `check.ai_run_id`、`business_ref`、旧 `commute-ai:` 键三种证据找已提交任务。
2. 找到则采用并补写关联（显式提交），随后用保存的输入恢复同一运行。
3. 找不到才 `create_ai_task(purpose=commute_internal, trigger=manual|schedule,
   business_ref=check_id, idempotency_key=commute:<check_id>:v1)`；`attach` 在提交前
   写入 `check.ai_run_id`。
4. 同一 check 的输入固定：重试沿用 `request_text`，路线摘要重算不会生成第二个运行。
   修改计划或用户显式重新分析会产生新的 check 与新任务。

**未来功能**（日志整理、工作提醒、旅游建议）
新增一条 `AiTaskSpec`（用途名、输入版本、`prepare_input`、`validate_result`）即可复用
创建、Nexus 调用、轮询、取消与恢复；本轮没有为它们建空接口或空表。

## 5. 旧数据

`scripts/backfill_user_asks.py` 只在**独立副本**上操作：复制源库 → 迁移 → 分类 → 统计，
并校验源库哈希不变。分类只用结构性证据：

| 证据 | 判定 | 处理 |
|---|---|---|
| `commute_checks.ai_run_id` 指向该运行 | 通勤内部任务 | 设 purpose；有 check 时补 `business_ref`/trigger |
| 键以 `commute-ai:` 或 `commute:` 开头 | 通勤内部任务 | 同上；check 不存在时 `business_ref` 留空并计入报告 |
| 以上都没有 | 普通聊天 | 建 `user_asks`，`business_ref` 指向该提问 |
| 幂等键为空等无法判定 | `legacy_unknown` | 保留、不建提问关联、报告原因 |

不按提示词文字分类；不因为有 check 关联就删除更早的运行；一条 check 曾关联多个运行时
全部保留，新代码优先复用最早的关联；不通过重调模型补历史。

仍无法分类的情况：键为空或来源标记不在已知集合内的运行（会被列为
`legacy_unknown`，保留且不进入聊天历史）；check 已被删除但键标记仍在的内部运行
（保留为内部任务，`business_ref` 留空）。两种情况都会在脚本输出的
`unknown_runs` / `commute_without_check` 中列出，等待人工确认。

**旧客户端缓存核对**：`POST /api/v1/asks/verify`，最多 50 个 id，只返回
`chat` / `not_chat` / `unknown`，不含请求文本或内部指令。
`unknown` 包含“不属于当前账号”“已删除”“迁移前无法判定”三种情况；客户端不得据此删除。
“没有出现在最近一页”只说明不在 `created_at` 前 N 条内，同样不是删除依据。

## 6. 天气与建议适用性

- 权威关联是 `commute_weather_snapshots.check_id`（唯一）。`commute_checks.weather_snapshot_id`
  与 `eta_snapshot_id` 从未写入，已标注为废弃占位，读取方只能走快照侧。
- 天气接口按“计划 + 出行日期（缺省为计划时区的今天）”取最新一条可用快照，
  返回 `fetched_at`、`valid_from`、`valid_to`、`provider`、`quality`、`coverage`、
  `is_stale`、`stale_after_seconds`、`matches_current_plan`、`current_plan_revision`。
  没有记录返回 404 `NO_WEATHER`，不会借用其他日期或旧地点。
- 建议继续返回生成时保存的 `weather_json` 与 `sources`；新天气不会覆盖旧建议。
- 读取时计算 `matches_current_plan`、`is_current_service_date`、`is_expired`，
  `latest` 仍表示“最近保存的建议”，不会被偷偷改成“当前有效建议”。

## 9. 客户端（未改代码，供接入参考）

**聊天历史**：继续用 `GET /api/v1/asks`（现在是提问关联查询）与
`GET /api/v1/asks/{local_run_id}`；字段与标识未变，本地保存的 `local_run_id` 继续有效。

**旧缓存**：`POST /api/v1/asks/verify`，body `{"local_run_ids": [...]}`（1..50）。
- `chat`：可保留为聊天。
- `not_chat`：内部任务，应当从聊天缓存移除（或折叠到内部区域）。
- `unknown`：保留并稍后重试，禁止删除；404/5xx 也不等于“应删除”。

**天气**：`GET /api/v1/commute-plans/{plan_id}/weather`（可选 `local_service_date`）。
用它显示“最新天气”，同时继续用建议里的 `weather` + `sources` 显示“上一次分析采用的天气”；
两者不一致是正常的，不要互相覆盖。`is_stale=`true 时说明天气已超出新鲜度窗口。

**建议适用性**：`matches_current_plan=false` 显示“计划已修改”；
`is_current_service_date=false` 显示“历史建议”；`is_expired=true` 显示“已过期”。
三项都是读取时计算的说明，不改变历史模型输出。

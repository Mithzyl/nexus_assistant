## 2. 复用评估（先评估再建表）

| 既有结构 | 能复用的部分 | 需要扩展/不采用 | 结论 |
|---|---|---|---|
| schedules 日程表 | 表本身、标题/起止/地点、按日期窗口查询、只读日历工具 | 增加 matter_id、source、sync_status、source_external_id、source_updated_at、source_version、data_source_id、latitude/longitude、deleted_at；source_run_id 保持“哪个 AI 运行创建” | 扩展，不新建同义日程表 |
| tasks 待办表 | 标题/状态/截止时间 | due_at 是截止而非提醒；没有事项关联、顺序、完成历史与提醒关系。强行扩列会改变旧任务含义 | 不复用；事项待办用 matter_todos |
| BusinessRecord | 账目金额与业务记录 | 不是持续事项容器，也没有进展历史/关联日程 | 不把事项生命周期塞入账目 |
| notification_outbox 通勤提醒 | 已发送记录/尝试次数/失败语义 | 绑定 plan_id/instance_id 与固定提醒时隙，由通勤 worker 投递；事项提醒生命周期不同 | 不复用；新增 reminders，本轮不新建投递机制 |
| content_sources/items | 来源归属、授权、批次幂等、版本防覆盖 | source_type（calendar/reminders/notes）与记录 source（web_native/ios_eventkit/ios_reminders）语义不同 | 保留三套概念，不互相替换；iOS 快照复用来源与批次表 |
| /asks | Nexus 运行、SSE、取消/恢复、问答历史 | 运行标识不是事项标识；answer 文本不等于业务数据已保存 | 只复用 AI 任务/运行机制，事项落库另行校验与确认 |

### 2.1 新增表与原因

- matters：标题、目标、状态（active/waiting/archived/deleted）、版本、下一步、最后进展时间、归档/删除时间。
- matter_todos：属于事项的待办子项，含 due_at（截止）与 reminder_at（提醒触发）；二者不混用。
- matter_progress：追加式进展历史，记录用户原话与 AI 运行来源。
- matter_drafts：待确认变更（预览），含版本、基线事项版本、基线日程更新时间、确认幂等键、冲突快照、候选事项。
- matter_changes：确认后实际变更前后快照，用于纠正/撤回。
- reminders：通用提醒记录（内容、触发时间、关联事项/待办、状态、同步状态、执行结果）。本轮只存不投递，原因见 §8。

## 3. 迁移

    cd services/assistant-api
    .venv/bin/python -m scripts.migrate_sqlite upgrade --database "sqlite+aiosqlite:///data/local-development.db"

- 空库：init 直接用当前元数据建表。
- 旧库：upgrade 只做 ALTER TABLE schedules ADD COLUMN ... NULL 与幂等索引，记录 0007_matters；不会删除或重建库。
- 回滚：代码回退后旧代码忽略新列；新表可保留（不参与旧逻辑）。没有破坏性回滚脚本。

## 4. 时间、时区与状态

- 所有响应时间为 UTC ISO-8601（Z）。数据库按 UTC 墙钟存储，服务层统一转为 UTC。
- 请求可带偏移；无偏移的模型输出按用户 profile 时区（缺省 Asia/Shanghai）解释后转 UTC。服务端只接受绝对时间，“下周四”由模型结合 now/timezone 解析。
- 事项状态：active（正在推进）、waiting（等待外部反馈）、archived、deleted（软删）。
- 草稿状态：preview、confirmed、cancelled。
- 日程来源：web_native、ios_eventkit；提醒来源：web_native、ios_reminders。
- 同步状态：local_only、pending_ios、ios_synced。
- 提醒状态：pending、completed、cancelled。
- 未定命名：原文 web_confirmed_pending_ios 与模块一 pending_ios 的对应仍未确认（附录 C-2），本轮机器状态用 pending_ios，未把两者强行等同。

## 5. 接口与字段

前缀 /api/v1。除登录外均需 Authorization: Bearer <token>；所有资源按登录用户隔离。

### 5.1 事项

| 方法/路径 | 说明 | 主要字段 |
|---|---|---|
| GET /matters?group=active|waiting|archived|all&limit=1..50&cursor= | 分组列表；按 updated_at 倒序 | items: matter_id,title,goal,status,version,next_step,last_progress_at,latest_progress,open_todos,created_at,updated_at；next_cursor 为下一页 offset 字符串（无更多为 null，采用 offset 分页） |
| POST /matters | 手工建事项（不写正式日程/提醒） | title(必填,1..255), goal(≤4000), next_step(≤500) |
| GET /matters/{id} | 详情 | 列表字段 + schedules[] + todos[] + progress[] + reminders[] |
| PATCH /matters/{id} | 纠正标题/目标/状态/下一步 | expected_version(必填), title?, goal?, status?=active|waiting, next_step?；版本不符 409 |
| POST /matters/{id}/archive | 停止跟进（归档） | expected_version, cancel_reminders=false；默认不取消提醒（C-3 未定） |
| POST /matters/{id}/reopen | 重新打开 | expected_version |
| DELETE /matters/{id} | 彻底删除（软删） | 同时软删关联日程、取消待发提醒、取消预览；删除后不再进入检索/模型上下文 |
| POST /matters/{id}/todos/{todo_id}/complete 或 /reopen | 勾选/取消待办 | 返回 todo |

字段：status 为事项状态；version 每次正式修改 +1；latest_progress 可为 null；open_todos 为未完成数。

### 5.2 自然语言接续（同一业务逻辑）

| 方法/路径 | 说明 |
|---|---|
| POST /matters/intake | 通用入口：{text(1..4000), idempotency_key(8..128)} → 201 {draft, replayed} |
| POST /matters/{id}/intake | 事项详情内“补充进展”，固定接续该事项，同一套服务逻辑 |

服务端流程：读取当前用户活跃事项（不含已删/归档）→ Nexus 输出 JSON → 服务端校验（所有权、绝对时间、范围、待办 id）→ 匹配事项 → 生成预览草稿（不写正式记录）。
- 匹配：模型可返回 matter_id；服务端校验属于本人且活跃。否则用标题二元组相似度兜底；多件同时匹配时返回 candidates 与 requires_choice=true，不擅自修改任何一件。
- 模型不可用/超时/结果未知/校验失败：返回 5xx 错误码，不生成草稿、不写业务表。

### 5.3 预览、修改、确认

| 方法/路径 | 说明 |
|---|---|
| GET /matters/drafts/{draft_id} | 读取预览（含冲突与候选） |
| PATCH /matters/drafts/{draft_id} | 修改标题/目标/备注/下一步/日程/待办/完成项；expected_version 必填；版本 +1 并重新计算冲突 |
| POST /matters/drafts/{draft_id}/confirm | 需 Idempotency-Key 头；body: expected_version, matter_id?(多候选时必选), create_schedule=true, sync_to_ios=false, acknowledge_conflict=false |
| POST /matters/drafts/{draft_id}/cancel | 取消预览 |

确认时的服务端限制（不依赖网页按钮）：
1. 草稿必须 preview 且版本匹配，否则 409 preview_stale。
2. 更新类：事项当前版本必须等于预览基线版本，否则 409 matter_changed。
3. 更新既有日程：日程 updated_at 必须等于预览时基线，否则 409 schedule_changed。
4. 当前仍有冲突且 acknowledge_conflict=false：409 conflict_detected（选项在预览里）。
5. 多候选未选：422 matter_choice_required。
6. 同一 Idempotency-Key 重复确认：返回首次结果（replayed=true），不新增记录；同键换草稿：409 idempotency_key_reused。
7. 确认才写：schedules / reminders / 待办完成 / 进展历史 / 变更记录；create_schedule=false 时不写日程（提醒仍按待办的 reminder_at 写）。
8. sync_to_ios 默认 false → sync_status=local_only；为 true → pending_ios。默认保守值是对 C-4 未定的实现选择，不是产品承诺。

ConfirmResponse：draft、matter、schedule(可 null)、reminders[]、change_id、replayed。

draft.payload 的稳定字段（网页可依赖）：
kind(create|update)、matter_id、requires_choice、title、goal、changes_note、next_step、schedule{schedule_id,title,starts_at,ends_at,location,latitude,longitude}、todos[{todo_id,title,due_at,reminder_at,status}]、complete_todo_ids、source_text、analysis{ai_run_id,confidence,dropped_complete_todo_ids}。
draft.conflicts：has_conflict、severity(none|tight|overlap)、window{start,end}、conflicts[]、options[]（见 §6）。

### 5.4 撤回

POST /matters/{matter_id}/changes/{change_id}/revert：恢复该次确认前的标题/目标/下一步；若该次新建了日程则软删该日程，否则恢复日程字段；取消该次新建的待发提醒；追加一条撤回进展；再次撤回同一变更 409 already_reverted。

### 5.5 今天与提醒

- GET /today?date=YYYY-MM-DD：按用户时区取当天；返回 date、timezone、schedules[]、reminders[]（仅 pending）、pending_drafts。
- GET /reminders?from&to&status=：按触发时间过滤，返回提醒记录；不代表已发送通知。

### 5.6 独立通勤测算

POST /commute/estimate（方法为本实现选择，原文未规定 GET）
请求：origin{latitude,longitude}、destination{...}、mode=driving|walking、depart_at 或 arrive_by（至少一个）。
响应：status=available|unavailable、provider、duration_seconds、distance_meters、fetched_at、request_depart_at、target_arrival_at、source=server_provider、reason_code。
- Provider 未配置/失败 → 200 + status=unavailable + reason_code（route_provider_unavailable / route_provider_error），不返回剧本数字。
- 不要求先建通勤计划；与 /commute-plans/{id}/checks 的固定计划逻辑互不复用状态。

### 5.7 iOS 同步预留

POST /sync/ios/snapshot：
{source_id, batch_id, records:[{external_id,last_modified_at,deleted?,title,starts_at,ends_at,due_at,location,status,version?}], removed_external_ids:[]}
- 复用 content_sources 归属/上传开关与 content_sync_batches 批次幂等；来源类型必须 calendar/reminders。
- last_modified_at 存为 source_updated_at；updated_at 仍是服务端编辑时间；source_version 取传入 version 或时间戳秒。不新增含义重复的时间列。
- 旧 last_modified_at 不覆盖新副本；同 batch 重放返回原统计；未出现在本批的记录不视为删除；显式 removed_external_ids 或 deleted=true 才软删。
- 响应：batch_id、source(ios_eventkit|ios_reminders)、created/updated/unchanged/removed、last_sync_at、replayed。
- 导入记录 sync_status=ios_synced（它来自苹果端）。

GET /sync/ios/pending-actions：返回 sync_status=pending_ios 的日程/提醒，payload + note。只代表等待苹果端执行，不代表已写入。回调/确认契约尚未确定，本轮不新增第四个接口（附录 D1）。

### 5.8 冲突规则

- 窗口：拟议开始前 3 小时至结束前后 3 小时（matter_conflict_window_hours），包含内置日程序列与已上传苹果日程。
- 苹果导入日程只有在其来源 assistant_enabled=true 时参与，未扩大读取授权。
- 与“上一条结束 → 本条开始”的间隔比较：需要 ETA + 15 分钟；不足或重叠 → tight|overlap，返回 2~3 个选项（A 推迟本次、B 调整上一条并生成联系待办、C 保持时间提前出发）。ETA 不可用时明确 eta_status=unavailable，不编造时间。
- 修改时间/地点后 PATCH 预览即重算；确认时再次重算，冲突未确认返回 409。

## 6. 错误码与请求语义

| 场景 | HTTP | code |
|---|---|---|
| 事项/草稿/待办/变更/日程不存在或不属于本人 | 404 | matter_not_found / draft_not_found / todo_not_found / change_not_found / schedule_not_found |
| 预览版本过期 | 409 | preview_stale |
| 事项在预览后被修改 | 409 | matter_changed |
| 关联日程被修改 | 409 | schedule_changed |
| 未确认冲突 | 409 | conflict_detected |
| 多候选未选择 | 422 | matter_choice_required |
| 已确认/已取消草稿 | 409 | draft_already_confirmed / draft_cancelled |
| 幂等键复用 | 409 | idempotency_key_reused / confirm_race |
| 模型结果不合格/超时/失败/未知 | 422 / 504 / 502 | matter_extraction_invalid / matter_ai_timeout / matter_ai_failed / matter_ai_unknown |
| 来源不存在/关闭上传/类型不符 | 404 / 409 / 422 | source_not_found / source_sync_disabled / source_type_not_syncable |
| 快照记录无效 | 422 | snapshot_record_invalid |
| 归档事项继续补充 | 409 | matter_not_active |

- 超时：确认请求超时后用同一幂等键重试，或 GET 草稿/事项查看实际结果；不要盲目换键。
- 重复点击：intake 用同一 idempotency_key 返回同一草稿；confirm 同键返回首次结果。
- 账号切换：所有查询按 user_id 过滤；他人草稿/事项 404。删除后不再出现在列表、匹配上下文与今日。

## 7. 网页接入示例

    // 1) 问助手输入
    POST /api/v1/matters/intake
    {"text":"下周四下午三点去陆家嘴和林总谈合同，周二下班前让法务发修订版","idempotency_key":"web-intake-20261026-001"}

    // 2) 底部面板读取/修改/确认
    GET  /api/v1/matters/drafts/{draft_id}
    PATCH /api/v1/matters/drafts/{draft_id}
    {"expected_version":1,"title":"与林总洽谈年度合作合同","schedule":{"title":"与林总面谈","starts_at":"2026-11-05T15:00:00+08:00","ends_at":"2026-11-05T16:00:00+08:00","location":"陆家嘴"}}

    // 3) 用户点 [确认更新]
    POST /api/v1/matters/drafts/{draft_id}/confirm
    Idempotency-Key: web-confirm-20261026-001
    {"expected_version":2,"acknowledge_conflict":true}

    // 4) 重新读取真实结果
    GET  /api/v1/matters/{matter_id}
    GET  /api/v1/today

页面文案建议：只按实际 sync_status 展示。local_only → “已记入应用内日程”；pending_ios → “已记入应用内日程（待 iOS 客户端同步）”；ios_synced → “已同步自苹果端/已同步”。不得显示“已写入 iPhone 系统日历”，除非记录确实 ios_synced 且来源可核实。

## 10. 与原文差异/实现边界

- 原文只确定 iOS 接口路径与字段语义；本实现新增的具体路径/名字（如 /matters/intake、draft、confirm）标注为本次实现设计，不冒充原文指定。

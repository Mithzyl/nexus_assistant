本轮补齐结构化创建及完整通勤草稿入口，复用现有 MatterDraft、patch_draft、confirm_draft 和 commute_bundle；没有新增另一套待办、日程或提醒保存实现。没有修改业务数据库、前端或现有 8010 进程，没有提交、推送。代码及本次定向验收已完成；真实模型生成、真实供应商和当前 Web 的运行验收未执行，不能据此称线上行为已验证。

## 复核发现与修正

| 原情况 | 本轮处理 |
| --- | --- |
| 只有空事项创建、已有对象编辑入口可供通用规划器调用，从零新增待办无法连续保存 | 新增结构化草稿入口，调用既有保存事务；不需要先创建空事项 |
| 完整通勤创建仍藏在旧意图流程内，单独创建周期配置无法满足首日日程前提 | 发布已有组合草稿创建逻辑，提供候选→测算→保存步骤；区别周期配置接口 |
| 可省略请求体被通用调用强制转换为空对象 | 区分没有请求体与空JSON对象，复用原接口可选请求体语义 |
| 只有各接口输入，没有发布下一步依赖和响应定义 | 从路由 x-assistant.next 自动解析后续接口；返回被选接口的输入、响应 schema 及其引用组件 |
| 修改对象 XOR、路线起点条件、跟进触发条件只在 Python validator 内存在 | 同步发布 oneOf/allOf/anyOf 等条件；不能由 JSON Schema 表达的时间比较、所有权、实时版本由服务端校验，说明写在字段和接口描述中 |
| 地点查询被标为写入、草稿方案被标为正式写入 | 修正 read/preview/write；preview 不是保存完成 |
| PUT 原计划时复制整份响应会夹带只读字段，版本头无法引用整数 | 新增通用 pick 字段投影和 as=string 本地绑定，原业务字段不交给 Nexus |
| 反复搜索与最后一步后直接落入固定追问 | 同一组目录返回重复检索提示；操作预算用尽后允许一次最终回答，不能再执行调用。仍不能给出最终答复时记录失败，而不假称用户缺少确认 |
| HTTP 200 但 applied=false，或 202 入队，可能被展示为操作完成 | 向模型提供 applied 标志；这两类结果不生成 completed 结果卡片 |
| 通知绑定、客户端设备事件、运行诊断混入业务目录 | 由原客户端入口处理，AI 目录不提供这些操作 |
| content 列表/详情仅校验账号及同步范围，没有按 assistant_enabled 筛选 | 不将这两个接口提供给 AI；原客户端读取行为保留。需要设备内容用于 AI 查询时，应复用已有授权过滤，而不能直接开放当前接口 |

## AI 获得的调用要求从哪里来

真实 HTTP 路由与 Pydantic 请求/响应类型是接口定义来源。Assistant 从 app.openapi() 建目录，按当前输入和允许的历史检索；Nexus 只得到被选接口及必要结构，不扫描代码，也不维护 Assistant 的业务目录。

业务接口继续使用已有认证、所有权、状态、版本和保存函数。新接口只需要正常发布 OpenAPI，通用执行器不增加 Python handler 字典条目。多步业务在对应路由发布步骤说明，不把接口到执行函数的另一份映射写进规划器。

| 路由 OpenAPI 字段 | 用途 |
| --- | --- |
| operationId | 调用标识，必须唯一，由当前 FastAPI 生成或显式指定 |
| summary / description | 检索用途、前提、字段含义、效果及下一步要求 |
| parameters / requestBody | 路径、查询、请求头、JSON 参数及必填、范围和条件 |
| responses | 成功和失败响应结构；引用组件按选中接口收集 |
| x-assistant.enabled | false 时不提供给 AI；reason 说明具体原因 |
| x-assistant.effect | read、preview 或 write；用于区分查询、准备步骤和正式写入 |
| x-assistant.keywords | 可选业务检索词，避免长描述中的反向说明抢占检索结果 |
| x-assistant.next | 可选数组：method、path、purpose；按当前 OpenAPI 解析 operation_id，不注册新执行代码 |
| x-assistant.required_headers | 可选：补充原服务实际要求的请求头。本轮 If-Match 保持原 HTTP 缺省时返回428，目录按必需项校验 |

这些字段是开发及调用说明，不直接呈现在用户卡片。当前目录最多选 8 个相关接口，优先包含最近实际操作声明的下一步；不把整个应用的 OpenAPI 发送给模型。模型仍可能选错接口或参数，实际执行以本地校验及真实响应为准。

## 组合入口与已有步骤

### 新增事项、待办或普通日程

`POST /api/v1/matters/drafts`，operation_id=`create_structured_draft`，effect=`preview`。

| 字段 | 类型与要求 |
| --- | --- |
| idempotency_key | 字符串8–128，相同请求使用同一个键；键被其他参数复用返回409 |
| matter_id | 追加到已有事项时提供真实ID；从零新建时省略 |
| expected_matter_version | 指定已有事项时必填，整数≥1，必须等于当前version；新建时省略 |
| title | 新建事项必填，1–255字符；追加时省略则保留原标题 |
| goal / next_step / changes_note | 复用 DraftPayload 中的字段，按实际意图提供 |
| schedule | 可选 NewSchedulePayload，title与starts_at必填；ends_at必须晚于开始时间，坐标必须成对，schedule_id只能为空 |
| todos | 最多30条 NewTodoPayload；每条title必填；due_at、reminder_at独立且可省略，todo_id只能为空 |
| complete_todo_ids | 此创建入口只允许空数组，完成原待办使用已有完成接口或修改流程 |

无 matter_id 时先保存 preview，confirm 时才创建 Matter、MatterTodo、ScheduleEvent 和 Reminder。已有 matter_id 时固定其当前版本；confirm 向该事项追加，不猜测、复用或替换某条同名日程。

完整调用示例（示例键、响应ID只是说明，真实执行必须引用返回值）：

```json
{"operation_id":"create_structured_draft","body":{"idempotency_key":"request-todo-preview-001","title":"弄清楚优惠销售品","todos":[{"title":"弄清楚优惠销售品"}]}}
```

响应是现有 DraftRead，包含 draft_id、version、status=preview、kind、payload；此时未保存正式待办。下一步：

```json
{"operation_id":"confirm_draft_api_v1_matters_drafts__draft_id__confirm_post","path_parameters":{"draft_id":{"$result":"/draft_id"}},"body":{"expected_version":{"$result":"/version"}}}
```

认证与 Idempotency-Key 由 Assistant 注入；请求体中的idempotency_key使用当轮上下文提供的调用键，每个步骤不同，重取同一步时保持相同。成功返回 ConfirmResponse；随后调用原 GET `/matters/{matter_id}`，matter_id引用`/matter/matter_id`，得到真实todos、schedules、reminders用于卡片。用户已经明确提出新增，不再要求点击确认。

### 修改同一条原记录

1. GET `/matters/{matter_id}`，以用户当前输入及允许历史的条件唯一定位原schedule_id或todo_id。
2. POST `/matters/{matter_id}/drafts`，idempotency_key必填，schedule_id和todo_id必须且只能一个。
3. PATCH `/matters/drafts/{draft_id}`，传草稿当前expected_version。日程用`{"$result":"/payload/schedule","overrides":{"title":"团建"}}`复制原完整对象并仅替换指定字段，原schedule_id保留。
4. POST `/matters/drafts/{draft_id}/confirm`，使用最新草稿版本，执行既有事务。冲突未应用时不报告成功。
5. 用真实 ConfirmResponse 或读取事项详情生成卡片；不通过重新创建来代替修改。

### 完整 PUT 与请求头参数

通勤计划 PUT 要求完整可写配置及当前 If-Match。可引用本地GET结果：

```json
{
  "operation_id":"update_commute_plan_api_v1_commute_plans__plan_id__put",
  "path_parameters":{"plan_id":"已查询确认的原plan_id"},
  "headers":{"If-Match":{"$result":"/revision","as":"string"}},
  "body":{
    "$result":"",
    "pick":["name","effective_from","enabled","timezone","weekdays","arrival_local_time","check_local_time","transport_mode","buffer_minutes","rain_probability_threshold","rain_extra_buffer_minutes","notify_enabled","origin","destination"],
    "overrides":{"name":"新通勤"}
  }
}
```

pick仅选择当前响应中真实存在的字段，保留原值；as=string只转换标量，不执行代码。$result可加step引用早先保存的成功响应。where必须唯一匹配，不能按数组位置猜选多条记录。所有引用在本地解析，之后再按目标接口校验。请求头最终必须为字符串，认证信息不能由模型提供。

### 完整通勤安排

`POST /api/v1/matters/commute-drafts`，operation_id=`create_commute_draft`，复用 commute_bundle.create_draft。

输入：idempotency_key、origin_query、destination_query、city、arrival_local_time必填；title默认“日常通勤安排”；effective_from、weekdays、buffer_minutes可暂缺，测算前需明确。weekdays为1–7整数列表，时间为HH:mm。不需要AI伪造坐标。

响应：DraftRead，payload.commute中包含intent、timezone、origin_search、destination_search和真实候选。引用唯一选择的selection_token，调用已有 `/matters/drafts/{draft_id}/commute-quote`，提供expected_version、origin_token、destination_token、effective_from、weekdays、buffer_minutes、mode。普通调用保留test_only=false。测算返回新的草稿版本，再confirm保存完整事项、首日日程和周期计划。后续generate-day要求该计划仍启用、matter_id及first_schedule_id有效、日期在生效周期内且未过目标到达时间。

直接 POST `/commute-plans` 仍然只创建周期配置，不能当作完整通勤安排保存完成。

### 跟进、提醒及状态动作

跟进沿用 create/get/patch/executions：先读取原业务记录，保存只读接口引用与唯一条件；时间触发在at和source中二选一，record_changed需要reference及非空fields。evaluate只检查提示，execute用于用户已明确授权的后续修改。暂停、恢复、结束用当前expected_version，不再次请求确认。

待办完成、恢复，提醒知晓，事项归档、恢复、撤回继续调用原接口；它们的效果不同，description已逐项说明。例如知晓提醒不会完成待办；归档默认取消未来日程，保留时应传cancel_future_schedules=false；是否取消提醒由用户要求决定。

## 提示词与本地执行

正式提示词仍是 services/assistant-api/src/assistant_api/services/matter_plan.py 的 API_PROMPT，INPUT_VERSION=15。组织当前输入、允许历史、检索到的api_operations、execution_results结构、card_schema、时间时区、remaining_steps与catalog_feedback。

AI每次返回call、search、ask_user/clarify或answer。每次只提出一个调用。description和next_operations要求连续到实际保存；没有历史的新用户直接依据本次输入和创建接口；原目标不唯一则询问具体条件，不增加确认步骤。最终语气平易近人，例如“待办加好了。”，具体字段放真实结果卡片，不展示内部步骤、HTTP状态、缺失的可选结果或诊断说明。

本地解析operation_id→当前发布的方法路径→解析$result→校验参数和版本→使用原认证执行ASGI HTTP调用→保留真实响应本地→向AI提供状态、HTTP码、必要引用、applied、error_code及result_shape→解析AI回答和通用卡片。不会执行AI提供的URL、curl命令或Python函数名。

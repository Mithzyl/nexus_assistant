## 职责和保存方式

- calendar_records.py：仅创建或条件更新日程，不创建待办，不提交事务。
- todo_records.py：仅保存待办字段及完成状态，不创建日程，不提交事务。
- reminder_records.py：维护提醒归属、绝对时间或明确的相对时间依赖，不推断“同事项即关联”。
- record_commands.py：把单独创建/修改作为一个完整业务命令暴露，内部复用原草稿版本检查、历史与confirm_draft事务；调用方无需先创建空事项、打开草稿或再确认。
- confirm_draft：作为组合保存入口调用上述独立保存函数，在一个正式事务中统一提交或回滚。

Matter仍是共同归属；MatterTodo与Schedule平级。新建日程不自动生成待办；新建待办不要求日程。单独请求没指定matter_id时，后端在正式保存事务中建立所属事项，不把创建父记录交给AI另行猜测。

## 独立业务接口

全部使用原CurrentUser身份校验，Web与AI调用同一Controller和Service。operation_id均来自当前OpenAPI，不添加TOOLS执行映射。

| 方法与路径 | operation_id | 业务行为 |
| --- | --- | --- |
| POST /api/v1/todos | create_todo | 一次保存待办及必要的父事项，返回实际todo |
| GET /api/v1/todos | list_todos | 按query标题字面条件、可选matter_id及limit查找原待办 |
| GET /api/v1/todos/{todo_id} | get_todo | 返回原待办、所属事项version及待办自己的提醒 |
| PATCH /api/v1/todos/{todo_id} | update_todo | 仅修改指定字段，保留todo_id；status=done完成、open恢复 |
| POST /api/v1/schedules | create_schedule | 一次保存日程及可选的日程提醒，不创建待办 |
| GET /api/v1/schedules | list_schedules | 按query、可选matter_id及limit查找原日程 |
| GET /api/v1/schedules/{schedule_id} | get_schedule | 返回原日程、所属事项version和日程自己的提醒 |
| PATCH /api/v1/schedules/{schedule_id} | update_schedule | 修改同一日程，未传字段保留 |
| DELETE /api/v1/schedules/{schedule_id} | cancel_schedule | 沿用原规则取消指定未来日程，保留事项和待办 |

列表limit默认30、最大50；query最长255。多条结果不能按数组下标猜选。取消日程要求查询参数expected_matter_version≥1及Idempotency-Key头（8–128字符）；通用执行器自动提供该头。

### 创建参数

共同字段：idempotency_key（8–128字符）；matter_id可省略；指定已有matter_id时expected_matter_version必须是该事项当前version，新建父事项时不提供版本。相同键及参数复用同一结果，换参数复用同一键返回409。

待办字段：title必填1–255；due_at可选；status默认open；提醒选下表的一种。独立待办的显式相对提醒需要真实日程ID，并提供该日程所属matter_id和当前版本。创建接口不接受原todo_id来代替修改。

日程字段：title、starts_at必填；ends_at、location和地点字段可选；结束时间必须晚于开始，坐标成对。提醒可省略；不会因日程存在而生成同名待办。创建接口不接受原schedule_id来代替修改。完整字段与长度以[OpenAPI](../commute/openapi.json)为准。

| 提醒要求 | 参数 | 归属及更新行为 |
| --- | --- | --- |
| 待办固定时间提醒 | reminder_at | 只绑定todo；移动或取消同事项日程不影响它 |
| 待办在某日程前后提醒 | schedule_reminder: {schedule_id, offset_seconds} | 明确绑定所选日程；日程移动时只重算此提醒，待办截止时间不变 |
| 日程自身固定时间提醒 | reminder_at | 只绑定schedule，不创建待办；改日程开始时间不改变这个绝对时刻 |
| 日程自身提前/延后提醒 | reminder_offset_seconds | 只绑定schedule并保留相对间隔，不创建待办 |

相对秒数范围±31536000，提前为负。一个对象的绝对提醒和相对提醒二选一。组合草稿明确要求依赖本次新日程时，todo.schedule_reminder可以省略schedule_id，保存事务绑定实际新ID；没有这种明确要求就不绑定。

示例：

```json
{"idempotency_key":"todo-example-001","title":"整理销售品清单"}
```

```json
{"idempotency_key":"schedule-example-001","title":"产品讨论","starts_at":"2030-05-09T15:00:00+08:00","location":"会议室A","reminder_offset_seconds":-1800}
```

### 修改与结果

PATCH共同必填idempotency_key、expected_matter_version；仅提供要修改的字段。待办支持title、due_at、reminder_at、schedule_reminder、status；日程支持title、starts_at、ends_at、location、坐标和地点字段、reminder_at、reminder_offset_seconds。nullable字段显式null用于清除；title、starts_at、status等实际必填值不能设为null。

读取接口返回matter.version供后续修改使用。独立修改不会改事项标题，也不会改另一类记录。更改待办提醒方式时新方式替换原方式；完成待办取消其待发送提醒。取消日程只取消日程自己的提醒和明确依赖它的提醒，不删除、完成待办或取消独立待办提醒。设备导入记录沿用原只读规则；ID不存在或不属于当前用户返回404，版本变化409。

创建和修改响应含实际matter、todo或schedule、相关reminders、change_id、replayed和applied。结果已足够展示时AI直接回答，不增加验证GET。接口按实际返回资源展示，不要求用户查看空的可选内容或内部诊断字段。结果卡片仍复用通用fields、text、image、timeline协议。

```json
{"decision":"call","call":{"operation_id":"create_todo","body":{"idempotency_key":"本轮上下文提供的键","title":"整理销售品清单"},"summary":"新增整理销售品清单待办"}}
```

成功后卡片字段可引用/ todo/title（实际JSON Pointer为`/todo/title`）；日程名称和时间引用`/schedule/title`、`/schedule/starts_at`；提醒时间引用真实reminders元素的trigger_at。普通创建只需一次业务调用及AI最终回答。

## 可选组合与事务

原POST /matters/drafts和confirm保存接口继续存在。schedule可省略，todos默认空；可以只创建一类，也可以组合。confirm_draft已使用同一组独立保存函数，并新增返回实际受影响todos。任一目标不合法或依赖日程不属于该用户时，整个正式事务回滚；preview可以保留，但不留下部分事项或日程。稍后单独添加待办失败，不撤销以前已经保存的日程。

## 提供给AI的说明与通用流程修正

正式matter_plan输入版本15。实际调用时提供：允许的输入和历史、最多8个相关接口、共用components.schemas、严格decision_schema、必要执行回执、result_shape和卡片Schema。接口用途、字段、实际约束和效果写在Controller/Pydantic定义中，Assistant自动检索；Nexus不维护接口目录，也不扫描代码。

单独创建优先使用独立接口；修改前查原ID及事项版本；不把创建事项当成创建待办；不增加确认选项。信息不足用ask_user。参数引用不能唯一匹配时，不发送业务请求，将固定校验反馈返回AI，由AI提出具体日期/地点问题。Schema不合法的调用继续拒绝，不执行模型提供的URL、代码、身份或未发布接口。

真实验收还修正了两个实际中断原因：

1. Nexus首次POST事件响应可以是有限批次。客户端现在使用同一workflow ID和Last-Event-ID只读续取GET事件，直到终态或超时，不重新创建Run或工作流。此前模型已完成但Assistant误判nexus_event_stream_incomplete。
2. 所选接口逐个附带相同Schema会超过Nexus的100000字符请求限制。现在组件只在根components.schemas提供一份，保留完整所选定义；决策返回的允许字段由decision_schema明确提供。

## 行为和范围

浏览器明确允许通知并保存 PushSubscription 后，服务端 worker 通过 Web Push 发送加密消息，Service Worker 展示系统通知。页面关闭后不依靠页面计时器继续运行；需要浏览器后台能力、联网和操作系统许可，浏览器完全退出或设备离线时可能延迟。

- 待办：优先使用显式提醒，未设置提醒时使用截止时间；已完成或删除的待办不发送。
- 日程：优先使用显式提醒，没有提醒时在开始时间通知；取消、删除和停止事项后不再发送。
- 通勤：已关联通勤计划的正式日程在出发时间发送；计划和通知开关必须开启。该功能不调用模型或重测地图；尚未生成正式出发日程的计划不会被编造时间或直接作为到期事件。
- 同一浏览器每个业务时间点只生成一次持久化派发。修改时间产生新的时间点；收到推送不完成待办、不确认提醒，也不表示设备日历已经同步。
- 仅派发浏览器启用后发生、最近 24 小时内的到期事件，不补发所有旧提醒。

`BrowserPushSubscription` 保存当前账号授权的浏览器能力；`BrowserPushDelivery` 区分 pending、sending、accepted、displayed、unknown、expired 和 cancelled。unknown 后收到有效展示回执可以更新为 displayed，不重新发送。accepted 仅表示推送服务接受；displayed 由 Service Worker 在 showNotification 成功后回报，仍不代表用户已读。结果未知不盲目重发，过期端点禁用。浏览器通知任务在后台 worker 的独立异步循环运行，不等待长 AI 任务。

## 配置与迁移

使用现有 Python 环境安装项目新增依赖 `pywebpush>=2.0,<3`。实际配置字段：

```text
ASSISTANT_WEB_PUSH_ENABLED=true
ASSISTANT_WEB_PUSH_PUBLIC_KEY=<公钥>
ASSISTANT_WEB_PUSH_PRIVATE_KEY_PATH=<长期保留的私钥文件绝对路径>
ASSISTANT_WEB_PUSH_CONTACT=mailto:<运维联系邮箱>
```

使用 `scripts/configure_web_push.py --directory <私有配置目录>` 生成一次密钥。已有密钥会复用；私钥文件 0600，输出只有公钥和文件路径，不写入已有 env。重启时保留同一密钥，不能每次启动更换，也不能提交私钥。

增量迁移 `0027_browser_push` 新增订阅和派发表。实际库先备份再升级；本次仅在隔离库建表，没有迁移正常开发库、替换其配置或重启现有服务。运行真实环境需要将配置交给原 API 和统一后台 worker，不能只启动网页。

## 业务接口

全部使用原账号会话鉴权，不进入 AI 业务目录：

| 接口 | 参数或结果 |
| --- | --- |
| GET `/api/v1/browser-notifications/config` | 返回配置可用性、公钥和当前账号订阅编号；不返回私钥、端点或浏览器认证密钥 |
| POST `/api/v1/browser-notifications/subscriptions` | JSON：endpoint、keys.p256dh、keys.auth；返回 subscription_id 与 enabled |
| DELETE `/api/v1/browser-notifications/subscriptions/{subscription_id}` | 仅禁用当前账号的订阅，保留历史 |
| POST `/api/v1/browser-notifications/receipts/{delivery_id}` | Service Worker 回报展示结果；只能操作当前账号的派发记录 |

前端同源代理使用 `/api/pa/browser-notifications/*`。新设置页 `/me/notifications` 明确申请权限；“我的”和“今天”提供入口。退出账号前取消该浏览器订阅。旧“今天”页的 new Notification 循环已删除，避免并行重复通知。

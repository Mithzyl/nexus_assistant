## 当前进度


业务记录采用哪条记忆的保存代码及直接依赖已进入 `a007643` 和 `22ddd5c`。2026-11-12 提交第 1、2 项，包含一次用户任务的 Nexus 运行、接口定义查询、工具请求归属校验和执行结果保存。2026-11-12 整理第 3 至 5 项。Assistant 在首次调用模型前读取本账号的相关记忆，提供本人记忆管理接口，并由后台进程在最终回答保存后执行已登记的记忆修改。本次只整理代码与说明，未重新运行验收。

| 顺序 | 工作内容 | 执行者、触发时机与结果 |
| --- | --- | --- |
| 1 | 一次用户任务沿用同一条模型执行记录 | Assistant 收到任务后，在负责调用模型的 Nexus 中创建一条处理记录，称为 Agent 运行。模型可以在这条记录对应的处理过程中多次请求工具。Assistant 校验并执行查询或写入，把实际结果返回原运行。Nexus 保留模型正文、工具参数和实际结果，供模型决定下一步或给出最终回答。 |
| 2 | 用服务端记录确认每次工具请求属于哪个账号和任务 | 网页请求的账号来自登录状态。Nexus 请求执行工具时，Assistant 先验证应用连接，再对照已保存的账号、Nexus 运行编号和工作流编号，在内部把账号及 Assistant 任务编号 `local_run_id` 交给业务接口。采用记忆时，业务接口据此核对该任务检索过的条目及版本。身份或任务对应不上时拒绝执行。 |
| 3 | 在第一次调用模型前读取当前账号的相关记忆 | Assistant 按当前输入和关联事项查询自己的记忆数据库，把相关记忆原文、编号和版本交给模型。候选不足时，模型可以请求 Assistant 补查。没有匹配、账号关闭记忆使用和查询失败分别记录。 |
| 4 | 让用户管理自己的记忆及历史版本 | 用户从记忆管理入口查看、新增、纠正或遗忘记忆，也可查看历史版本和设置记忆使用开关。Assistant 核对账号和版本后写入自己的数据库，保留原始来源与历史。模型提出的修改也由 Assistant 校验和执行。业务记录另行保存实际采用的记忆和版本。 |
| 5 | 在最终回答保存后执行可以延后的记忆修改 | 模型在当前运行中给出记忆操作。对于允许延后执行的操作，Assistant 把命令及重复请求标识存入数据库，返回等待处理的状态。最终回答成功保存后，Assistant 后台进程读取命令，核对记忆使用开关及条目版本，再写入结果。聊天失败或取消时取消待处理操作，版本冲突时记录失败供查询。后台执行已登记的命令无需再次调用模型。 |

例如，用户要求在会议前安排一条待办。Assistant 先读取该账号的时间习惯，Nexus 在同一次运行中先请求查询日程，再根据查询结果提出待办的截止时间。Assistant 校验账号、日程和记忆来源后保存待办，把实际结果交回该运行，Nexus 据此生成回答。

任务编号、接口参数及延后执行的状态见 [Assistant 保存记忆和处理一次聊天的规则](backend-integration/05-Agent-工具-记忆运行流程.md#职责与一次聊天的执行顺序)。

事项、独立日程/待办、提醒、iOS 同步接口、补充记录和通用跟进已有代码，不再安排从零建模。模型调用和同 Agent 消息继续由 Nexus 承担；Assistant 保留业务校验、执行、来源保存和页面数据转换。

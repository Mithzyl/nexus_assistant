| 1 | 随手记文字输入 | 从「今天」打开文字框，点「发送给助手」进入「问助手」。失败保留原文并以原请求编号重试。2026-11-18 隔离浏览器验收确认通勤测算、创建待办和刷新后查看问答历史 |
| 2 | 完善现有助手交互 | 普通成功回复按用户任务提供真实业务记录入口，不新增记忆来源入口；显示合理处理阶段与取消/未知结果状态；简化重复追问，保留卡片下方选项；登录后回原页面并保留未发送内容 |
| 3 | 五种交通方式与既有交互 | 补自行车/电动车选择及类型。后端本次已补待办/组合/周期通勤和明确重新应用的来源记录，常用库 0029/加载待执行；不新增前端来源入口，不把记忆全文自动放进正文，必要时由 AI 简述或用卡片；不增加偏好设置 |

## 二、已完成、不再作为待开发

真实事项列表/详情、日程/待办/提醒、补充/纠正/回答、跟进管理、结果卡片与 ask_user 已有。记忆管理的无效指令/共享入口已移除；作者来源、历史弹层和关闭焦点已修复；日程路线可选、重复提醒及内部文案已修复。地图组件、浏览器推送、manifest 与 standalone 已有，不再按旧 main 文档从零开发。

2026-11-10 已完成真实浏览器的“读取已有记忆和会议→创建一条带截止/提醒的待办→完成原待办”，首条卡片状态显示“未完成”。Web 已修复 cards=[] 仍展示旧回执卡片的问题：三项保存响应检查及 Chrome 重开历史通过，执行回执保留，提交 d976590 未推送；不再列为待开发。详情见[验收说明](测试与验收说明.md#空卡片列表与旧执行回执2026-11-10)。

这些基础存在不等于所有产品场景已验收。提醒秒数转换在后端已修改并加载，但未新增真实展示验收；目标浏览器通知与 iOS 真机仍独立准备。主屏幕安装与离线不是同一能力，不额外承诺离线业务写入。

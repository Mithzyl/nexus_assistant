# 界面文案规范与模板库

更新时间：2026-11-04。
适用范围：`apps/web` 中所有面向用户的文字，包括页面标题、按钮、字段标签、状态提示、空状态、错误、确认弹层和通知文案。代码注释、接口字段名、日志与内部诊断不在范围内。

## 0. 先问一句话

写每一句界面文字前，先问：**如果是一位真人助理当面向老板汇报，会这么说吗？**

- 会说：“明早可能下雨，我帮你多留了 10 分钟，建议 8:24 出门，大概 8:39 到公司。”
- 不会说：“建议出发 8:24，比上班早 36 分钟。未接实时路况。”

## 1. 六条铁律

### 1.1 报结果，不报算术过程

只给用户需要的时间点和实际余量，不让人在脑子里二次加减。

- 反例：`比上班早 36 分钟`、`距离截止 120 分钟前提醒`
- 正例：`预计 08:39 到达`、`提前 21 分钟到岗`、`截止前 2 小时提醒`
- 实现位置：`lib/mobile/advisory.ts`、`components/mobile/advisory-card.tsx`

### 1.2 用正面交代代替防御式免责

先说当前怎么帮上忙，再说明必要的边界；不要一上来罗列“没接什么、不保证什么”。

- 反例：`这条内容仅保存在当前设备，不会同步到云端。`
- 正例：`只留在这台设备上，换设备看不到。`
- 反例：`浏览器通知未获允许。`
- 正例：`只在页面内提醒你。`

### 1.3 同一屏核心词不连撞

同一个词不要在 Tab、卡片标题和相邻两行里反复出现。

- 反例：Tab「设置」→ 卡片「设置」→ 按钮「设置」
- 正例：Tab「通勤设置」→ 卡片「通勤安排」→ 按钮「调整计划」
- 反例：`到点提醒 · 提交报销单`（分区标题已写“到点提醒”）
- 正例：卡片标题只写 `提交报销单`

### 1.4 补全量词，去内部黑话

括号里的说明也要写完整，单位不能省；接口字段、错误码、版本号不上屏。

| 不上屏 | 用这个 |
|---|---|
| 服务器 / 云端 | 这里 / 账号 / 助手 |
| 字段、授权字段 | 信息、可同步的信息 |
| 错误码 `matter_ai_timeout` | 问题编号 `req_01J…`（仅在没有更具体原因时） |
| revision / version | 设置（必要时说“已更新”） |
| mock / stub | 演示数据 |
| JSON、OpenAPI、request_id | 不出现 |

- 反例：`错误码：matter_ai_timeout`
- 正例：`问题编号：req_01J…`（可提供给支持）
- 反例：`21 分钟 (雨天加 10)`
- 正例：`日常 11 分钟 + 雨天 10 分钟`

### 1.5 按钮用 2–6 字动宾结构

按钮是动作，不是句子；不用句号，不生造词。模板明确规定的长句按钮除外。

- 反例：`保存修改并重新核对`、`刷新这一天的路线`、`加一个日程`
- 正例：`保存并核对`、`刷新路线`、`新建日程`
- 例外：`已办完，一并完成待办` 是提醒模板原句，保留。

### 1.6 慎用感叹号与警告色

只有真实冲突、时间来不及、请求失败才使用琥珀色或柔和红；常规估算、正常归档保持平静。

- 反例：正常估算的 `08:24 !`；已归档事项显示“结果暂不确定”
- 正例：`⚠️ 与上午的日程时间冲突`；归档只写 `所属事项现已归档`

## 2. 四类模板

### 2.1 日程与出行

- 时间：`10月30日 周五`、`14:00 - 15:30`（两位小时与分钟）
- 已测算：`车程约 18 分钟 · 预计 08:42 到达`
- 待更新：`时间或地点已调整，点“刷新路线”`
- 有冲突：`两段行程间隔较紧，路上约需 30 分钟，建议微调时间`
- 天气：`19°C · 降雨概率 45%`
- 缓冲：`已包含 10 分钟雨天缓冲` / `日常 11 分钟 + 雨天 10 分钟`

### 2.2 状态与历史

- 待确认草稿：`已为你理清以下安排，确认后将记入日程`
- 已生效：`已确认并生效 · 已记入「{事项}」`
- 已归档：`当时已确认生效 · 所属事项现已归档`
- 已删除：`当时已确认生效 · 所属事项后来已被删除`
- 无感记忆：`✨ 已记住你的{常驻地点 / 通勤习惯} [撤销]`

### 2.3 按钮词典

| 场景 | 固定用词 |
|---|---|
| 发起 | `交给助手整理`（长内容）、`随手记一条`（速记） |
| 草稿 | `确认更新`、`确认并保存`、`保存并核对`、`微调内容` |
| 提醒 | `知道了`、`已办完，一并完成待办`、`继续这次提交` |
| 路线 | `刷新路线`、`测算路线`、`重新读取路线` |
| 记录 | `新建日程`、`新建待办`、`删除副本` |
| 生命周期 | `暂停跟进`、`恢复跟进`、`删除事项`、`放弃修改` |

### 2.4 空状态与登录引导

- 登录：标题 `登录生活助手`，说明 `跨设备同步你的今日安排、待办事项与个人习惯。`，按钮 `登录 / 注册账号`
- 今天：`今天暂时没有安排 · 有想做的事，随时交给助手整理。`
- 事项：`还没有正在跟进的事项 · 发一段消息或会议安排，助手会帮你理清头绪。`
- 个人记忆：`助手会在日常沟通中逐渐记住你的常去地点与作息习惯，你也可以随时在这里查看和管理。`

## 3. 改文案的固定步骤

1. 找到文案的渲染位置（页面、组件或 helper），确认它是否同时用于空值、错误和成功三种状态。
2. 核对事实：只有 `applied` 才能说保存；没有送达回执不说送达；演示数据不冒充真实。
3. 套模板，按钮查词典，标题检查同屏是否重复核心词。
4. 检查 390px 宽度下的换行与长度：按钮 2–6 字，说明尽量 1–2 行。
5. 运行 typecheck 与直接相关检查；改动第 5 节列出的文案前先看对应测试。

## 4. 自查命令

```bash
# 黑话、防御式用词、感叹号
grep -rnE "服务器|云端|错误码|revision|version|mock|stub|！" apps/web/app apps/web/components

# 按钮超过 6 个汉字
python3 - <<'PY'
import re, pathlib
pat = re.compile(r'>\s*([^<>{}\n]{2,40})\s*</button>')
for f in pathlib.Path("apps/web").rglob("*.tsx"):
    for m in pat.finditer(f.read_text()):
        label = m.group(1).strip()
        if len(re.findall(r"[\u4e00-\u9fa5]", label)) > 6:
            print(f"{f}: {label}")
PY
```

## 5. 受自动检查保护的文案

改动以下文字前先查对应检查，保持字符串不变或同步修改：

- `确认更新`：`tests/e2e/matters_enrichment_check.py`、`work_plan_check.py`、`matter_option_alignment_check.py`
- `刷新路线`：`tests/e2e/web_flow_check.py`
- `设置已更新`、`已过期`：`tests/e2e/web_flow_check.py`
- `模型分析未完成`：`tests/e2e/acceptance_model_flows.py`
- 已有数据时不得出现 `今天没有安排`（空状态断言）：`tests/e2e/work_plan_check.py`

## 6. 例外

- 隐私说明页的“我们不会做”是产品承诺，保留否定句。
- 演示与实验室页面必须写明与正式数据分开，不能用“已保存”描述本地示例。
- 失败详情保留可核对的事实（问题编号、时间），但不暴露内部错误码原文。
- 不能为了顺口弱化事实：没保存不能说已保存，没送达不能说已送达，没算出的路线不能写成“时间充裕”。

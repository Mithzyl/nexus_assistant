# 最新规划落地对照：现有能力与差距

> 本文不是产品规划，也不替代 [`产品规划-工作安排与计划接续.md`](产品规划-工作安排与计划接续.md)。它只回答一件事：最新规划提出的能力，仓库里现在有哪些、哪些能继续用、哪些还缺。
> 核对日期：2026-10-26。核对方式：只读查看当前 `main` 工作区代码、数据库模型、接口定义和既有文档；本轮没有运行测试、没有启动服务、没有修改业务代码。

## 1. 先给结论

- **可以直接复用的基础**：账号与会话、问答通道、数据来源与内容上传、通勤计划的路线与 ETA 计算能力、暖白／雾蓝视觉变量与深色模式、底部弹层组件与四栏导航框架。
- **需要扩展、不能直接当成已完成的能力**：`schedules` 日程表只有读工具和种子数据，没有写入接口、没有 `source`、没有 `sync_status`；`tasks` 只有标题/状态/截止时间，不是“事项”模型；通勤 ETA 只存在于检查流程中，没有独立的 `/api/v1/commute/estimate`。
- **当前完全缺失**：事项表与事项接口、提醒表、`/api/v1/sync/ios/snapshot`、`/api/v1/sync/ios/pending-actions`、`sync_status` 状态机、待确认变更卡与确认落库、跨对话事项匹配、前后 3 小时冲突检查与 15 分钟余量规则、PWA 添加到主屏幕全屏。
- **不能误判的部分**：现有 `/api/v1/data-sources/{source_id}/sync` 是 iOS 向 PA 的**只读副本上传**，不是 iOS 写回接口；现有事务页是**本地演示**，不是事项后端；现有通勤建议是**固定通勤计划**的检查结果，不是任意两地即时测算。

## 4. 仍缺或必须验证的部分

### 4.1 本轮代码已确认缺失

- 事项（Matter）表、事项接口、事项与日程/待办的关联、进展历史。
- 提醒表、提醒写入接口、提醒状态机。
- `POST /api/v1/sync/ios/snapshot`、`GET /api/v1/sync/ios/pending-actions`。
- `/api/v1/commute/estimate` 独立测算接口（原文未指定 HTTP 方法）。
- 每条日程/提醒的 `sync_status` 与 `source` 字段。
- 问助手的【待确认变更小卡】、确认后落库、撤回。
- 跨对话事项匹配、前后 3 小时日程冲突检查、15 分钟余量规则、2～3 个调整方案。
- Web App Manifest 与添加到主屏幕全屏配置。

### 4.2 已有实现但尚未验证到规划要求

- 通勤 ETA：现有检查流程可计算 ETA，但据 2026-10-25 记录，8010 联调环境没有可用的服务端路线 Provider；历史建议只能读取，不能称为“本轮重新完成的服务端路线分析”（见 [`移动Web通勤分析推进记录.md`](移动Web通勤分析推进记录.md)）。
- 通勤建议的 AI 分析：已有模型结果流程与隔离验证记录，本轮未调用真实 Nexus、天气或路线服务；既有真实调用记录不能代替最新规划整条业务链的验收。
- iOS 数据上传：EventKit 只读快照、字段授权和内容查询已有实现；端到端“Swift EventKit → 云端同步 → Agent 查询”仍需单独核对。
- 现有四栏导航与演示事务页：视觉和交互可用，但不是规划中的“事项/问助手”职责。

### 4.3 既有测试证据（引用，不当作本轮结果）

- [`acceptance-round1.md`](acceptance-round1.md)：2026-10-25 记录后端 180 passed、网页 `test:e2e` 90/90、iOS 单元 124/124、真实后台流程 29/29 等。
- [`移动Web实现与验证.md`](移动Web实现与验证.md)：2026-10-25 记录网页 90/90、`tsc` 与 `next build` 通过；隔离库、固定时钟、Playwright，不等同真实 iPhone Safari。

## 5. 建议的核对顺序（不改变规划优先级）

1. 先确认“事项”与现有 `tasks`、演示事务的关系，避免新建重复模型。
2. 设计日程/提醒的 `source` 与 `sync_status` 存储及关联；内置和已上传苹果日程参与冲突检查已定。
3. 保留原文 `snapshot` 路径并复用已有上传服务，明确字段适配和 `pending-actions` 回写结果边界。
4. 最后确认 `/commute/estimate` 与现有通勤检查 Provider 的复用边界。

以上顺序只是核对顺序，不是对开发顺序或工期的安排。

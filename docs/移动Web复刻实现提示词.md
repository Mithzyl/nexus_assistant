## 4. 产品与视觉目标

面向个人用户，帮助用户查看今天的事情和通勤建议、收集内容、查看事务、向助手提问，以及管理来源、授权、账号和提醒。

保留四个主入口：**今天、事务、助手、我的**。保持中文表达和原有层级，不改成管理后台、统计仪表盘或 AI 平台控制台。

视觉以当前 `Theme.swift` 为准：

- 暖白背景、雾蓝主色，内容使用稳定的实色表面。
- 半透明效果主要用于导航、工具栏和少量入口。
- 保留深色模式、字体层级、圆角、留白和轻量分隔。
- 已观察到的浅色值：背景 `#FAF9F4`、正文 `#293E4B`、主色 `#527C98`、深主色 `#3C5F73`、分隔线 `#E2E6E1`。实施时核对并整理为 CSS 变量。

移动交互要求：

- 约 390px 为主要设计参考，同时检查 360px、430px 等宽度。
- 处理安全区、浏览器动态工具栏、软键盘和输入区遮挡。
- 底部导航不覆盖正文或按钮，详情支持返回与刷新恢复。
- 切换标签不丢失未提交输入；弹层和表单在键盘出现时可用。
- 长标题、回答、列表和 Markdown 表格不撑破布局。
- 主要点击区域建议至少 44px，支持基本键盘操作和可访问名称。
- 桌面浏览保持合理内容宽度，不无限拉宽手机布局。

不模拟手机外壳和系统状态栏，不为填满页面增加无用统计卡片、技术说明或按钮。

## 6. 页面与业务任务

### 6.1 应用框架

实现四个主入口、页面头部、详情返回、底部导航和内容录入弹层。区分主页面、详情路由与弹层，浏览器返回不反复跳转。

统一加载、空结果、失败、未登录和完成反馈，但不要让所有页面套同一个大卡片模板。

### 6.2 今天

参考 `TodayView.swift`，实现日期标题、“收下内容”“记一句”、通勤卡片、待确认事项和最近整理记录。

日期来自当前时间，不复制示例日期。真实模式无数据时显示空状态，不自动填退款、电影或旅行示例。

每个快捷入口必须有可操作路径。提问、导入笔记和保存本地记录分别表达结果，不能统一提示“已整理完成”。

### 6.3 事务与详情

实现“进行中、已完成、全部”筛选，并核对退款、订单、来源、归属确认、票据、准备清单、心愿、安排、项目、旅行、新增结果等页面。

保留业务含义：商家发起退款不等于到账；金额相同不代表同一订单；勾选待联系不代表发消息；采纳建议不代表订票改签；本地安排不代表写入系统日历。

逐项确认后端接口。缺少接口的既有交互可在显式演示模式复刻；正常模式呈现真实空状态或能力说明，不以示例冒充服务器结果。分别报告页面复刻和后端接入的完成情况。

### 6.4 助手问答

优先完成真实登录后提交问题、处理状态、历史记录、最终回答、Markdown、取消和刷新恢复。

使用 `/api/v1/asks` 系列接口，字段与状态以当前代码为准：

- `202` 仅表示受理。
- `unknown` 表示结果未确定，不能显示成功或自动新建请求。
- 同次用户提交保留稳定请求标识，避免重复点击成为多次业务执行。
- 最终回答以 PA 查询返回的 `answer` 为准。
- 不把 Agent 中间输出、工具参数或内部事件当作最终答案。
- 不凭空增加后端未支持的连续会话、会话删除或历史分页。

如果使用 SSE，核对事件名称、序号和终态。当前事件接口是有限回放，连接结束不等于任务结束；结合游标和详情查询恢复状态，终态或离页清理订阅，避免重复追加内容。

根据认证方式选择 fetch 流或同源转发，不假设原生 EventSource 可以设置任意认证头。可先实现可靠查询，再接事件更新，不制作虚假百分比进度。

### 6.5 账号与会话

复用 PA 账号，完成登录、用户查询、登录态恢复、续期、退出和过期处理。已存在接口：

- `POST /api/v1/auth/login`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/session/renew`
- `POST /api/v1/auth/logout`

按当前 Next.js 部署方式选择同源服务端转发。新增 Cookie 适配时保留 iOS Bearer 语义。退出或切换账号清理旧状态、订阅和缓存；有效期以服务端为准。

不新增注册、找回密码、第三方登录或新的身份系统。

### 6.6 内容来源与同步

参考 `Sources/` 和 `docs/backend-integration/12-设备内容同步契约.md`，实现来源列表详情、云端内容搜索与详情、同步状态、授权、字段范围、删除副本或来源，以及支持的笔记导入。

三个独立概念必须保留：

- `sync_enabled`：继续上传。
- `assistant_enabled`：允许助手读取。
- `upload_fields`：允许上传的字段。

停止同步不等于删除，助手授权不等于用户是否可查看。按接口保留范围收窄、恢复及显式删除语义，不因本批次缺少某条内容就推断删除。

区分 iOS 采集来源和浏览器导入来源。Web 可读取已有云端副本，不冒充 iPhone 上传系统日历或提醒事项。

笔记导入只支持实际实现的格式，提供选择、预览、确认和结果反馈。选择文件不等于同步成功。不默认承诺 OCR、所有 Office 文件或读取 Apple 备忘录。

### 6.7 通勤与提醒

参考 `Commute/` 及后端接口，完成计划列表编辑、起终点与时间、手动检查、检查状态、建议详情和已有建议操作，以及 Bark 绑定、解绑、自动提醒开关和显式测试发送。

核对原生地图产生的参数。浏览器不能生成必要路线数据时，记录缺少能力，使用既有可用方案或限制编辑范围，不伪造坐标、距离、ETA 和路线快照。

不复用 iOS APNs 注册流程。后台调度仍由现有 scheduler/worker 承担，不依赖浏览器定时器。Bark 不等于 Web Push。没有通知历史接口时不构造已送达列表，不把 mock 结果写成真实天气、路线或推送验证。

### 6.8 我的、记忆与偏好

保留账号、来源、通勤、记忆、经验、隐私和说明入口，逐项核对真实能力。

`/memory/search` 在现有文档中是遗留代理，应核对后再接入。没有服务端支持的新增、编辑、删除、自动学习和偏好同步，不发明接口。演示交互明确限定为演示，不声称同步到 AI 平台。

隐私文案描述真实行为，只有保留期限或删除操作实际执行，才能做对应承诺。

## 7. AI 调用与数据职责

保持调用关系：

`移动浏览器 → Web 必要转发层 → assistant-api → llm_fusion_platform`

- Web：展示、输入、导航、交互状态和必要缓存。
- assistant-api：用户、业务数据、来源、通勤及 AI 请求转发。
- llm_fusion_platform：模型调用、Agent、工具调度和运行结果，仅复用现有能力。

不在 Web 新建供应商客户端，不向浏览器暴露平台令牌、模型密钥或 `role_bindings`。当前 PA 的 `general_agent / 1.0.0 / general_tools_v1` 由服务端维护。

不跨数据库查询，也不跳过 PA 将平台内部接口直接交给浏览器。缺少平台能力按第 2.1 节处理，禁止修改平台文件。

## 8. 原生能力的 Web 适配

| iOS 能力 | Web 处理 |
|---|---|
| EventKit 日历、提醒事项 | 查看已有云端副本，不声称获得系统读取权限 |
| Apple 备忘录 | 实际支持的文本或文件导入 |
| 地图与路线快照 | 核对参数来源，使用可用方案或明确限制 |
| APNs | 不使用原生设备注册流程 |
| Bark | 复用现有账号绑定接口 |
| 分享入口 | 先实现粘贴和文件选择，扩展分享能力另行验证 |
| Keychain | 使用适合当前 Web 架构的会话保存方式 |
| 原生返回与 Sheet | 浏览器路由、弹层和返回行为 |

PWA 安装、离线写入、Web Push 和后台同步不默认纳入核心范围。轻量安装入口不能被描述为完整离线能力。

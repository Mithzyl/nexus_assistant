### 发布前真实模型验收

在 Mac mini 使用隔离数据库、独立 Chrome 会话和真实 Nexus API、worker，运行 `opencode/glm-5.3-flash`。四组场景均通过，共 19 次模型调用。浏览器脚本有一次把输入框残留文字带入下一条测试，调整脚本后补验了受影响的场景。

| 场景 | 实测结果 |
| --- | --- |
| 连续对话改期 | 首轮直接调用 `create_schedule` 创建 10:00–10:30 的会议，省去接口定义查询。接着用同一日程编号执行 `get_schedule`、`update_schedule`，保存为 12:00–12:30。 |
| 刷新后续接与换话题 | 追问出现后刷新页面，打字补充时间并保存 15:00–15:30 的评审会。另一次刷新后，模型判断闰年问题属于新话题，关闭旧追问，日程数量保持不变。 |
| 随手记冲突与保存 | 录入撞车安排后，「今天」出现待确认卡片。模型在原时段先发起追问，随后按用户选定的 16:00 走正式保存接口，只保存一条复诊日程。 |
| 执行中刷新 | 查询日程和待办期间刷新浏览器，同一个请求恢复到最终回答和结果卡片，历史只有一条该任务记录。 |
